# v38 – V33 journey restoration and web deployment

The v33 road, background, company road and finish background assets are restored without redesign. Original v33 coordinate geometry is preserved. The personal runner now uses approved cumulative KM on successive 100-KM segments: 0–100, 100–200, etc. Checkpoint labels are 0/25/50/75/100 within each segment. The shared company runner follows cumulative approved KM from 0 to 50,000, visually capped at the finish; actual total is still displayed. Admin overview uses 0/10,000/20,000/30,000/40,000/50,000.

Deployment: upload the ZIP contents (not the ZIP itself) to the repository root of launch-test. Configure a separate Netlify site to deploy launch-test. Set STRAVA_CLIENT_ID, STRAVA_CLIENT_SECRET, STRAVA_VERIFY_TOKEN, SITE_URL, FIREBASE_SERVICE_ACCOUNT_JSON, AUTO_SYNC_ENABLED=true and PILOT_TEST_MODE=true for pre-October testing. Register the exact new-site webhook URL with Strava. If the Strava application already has an active subscription for the existing site, do not change it without planning a cutover. Deploy firestore.rules after reviewing them against your live project. Check function logs and test with a real Strava Run and Walk. Pilot activity before Oct 1 is stored separately and intentionally does not increase official campaign KM. On Oct 1, disable PILOT_TEST_MODE and deploy again.

IMPORTANT: Static/syntax checks are not an end-to-end test. Netlify scheduled functions and Strava webhook delivery require a deployed Netlify site and authorized Strava users. Do not claim auto-counting is confirmed until stravaEvents, stravaActivities, members.totalApprovedKm and UI all agree.
